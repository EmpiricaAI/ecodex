The objection

“Why not just use git worktrees?”

Fair question — and worth conceding the true part. Worktrees are the common parallel-agent pattern. We use them. But notice what they actually are.

A worktree solves execution isolation — a clean checkout so agents don't stomp each other's files. It carries code diffs. It says nothing about what an agent knew, with what confidence, or whether anyone approved the change. It's intra-repo, single-authority, code-only — the opposite of federation.

Governance

The gate hardens with distance

Inner rings flow open; outer rings are hard-gated.
  • ↳ identity is canonical + server-resolved — senders can't be spoofed
  • ↳ every actionable message traces to an ECO decision

The agentic-web failure modes — injection cascades, spoofed agents, runaway action with no accountability — don't land here. Openness is replaced by gated trust.

The reframe

It's a generalized pull request — over arbitrary shared state, not just code — where calibration is the review signal.

Worktrees parallelize one repo's branches. The mesh coordinates many sovereign agents' decisions. We use worktrees — for isolation. This is the layer above.
